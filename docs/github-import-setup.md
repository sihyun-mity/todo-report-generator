# GitHub 커밋 가져오기 — 설정 문서

금일 업무 진행 현황의 **GitHub에서 가져오기** 버튼은 마지막 보고서 이후(또는 오늘) 본인이 작성한 커밋을 불러와,
Chrome 내장 온디바이스 AI(Prompt API, Gemini Nano)로 프로젝트·작업을 분류한 뒤 폼에 채운다.

로그인한 **회원 전용** 기능이다. 게스트에게도 버튼은 보이지만 누르면 로그인 안내만 나온다.

## 1. 설정 — 로그인용 GitHub OAuth App 재사용

별도 OAuth App 은 만들지 않는다. Supabase GitHub 로그인에 이미 쓰는 OAuth App 을 그대로 쓰고,
"GitHub 연결" 시에만 `repo` 스코프를 추가로 요청한다.

- Supabase → Authentication → Sign In / Providers 에서 GitHub provider 가 켜져 있어야 한다.
- 이메일·패스키 회원은 GitHub 계정을 연동하는 단계가 함께 일어나므로 **Manual linking**(`linkIdentity`)이 켜져 있어야 한다
  (설정 → 소셜 계정 연동과 같은 조건).
- 환경 변수는 하나만 추가한다.

| 변수                         | 설명                                                         |
| ---------------------------- | ------------------------------------------------------------ |
| `GITHUB_TOKEN_COOKIE_SECRET` | 토큰 봉인 쿠키 암호화 키, 32자 이상 (`openssl rand -hex 32`) |

### 연결 흐름

1. 다이얼로그의 **GitHub 연결하기** → GitHub 가 이미 연동된 회원은 `signInWithOAuth`, 아니면 `linkIdentity` 를
   `scopes: 'repo'` 와 `redirectTo: /auth/callback` 으로 호출한다. 연결을 시작한 회원 id 와 복귀 경로는
   단기 쿠키(`trg-github-import`, 10분)로 넘긴다. `redirectTo` 에 쿼리를 붙이면 Supabase Redirect URL 허용 목록과
   어긋나 Site URL 로 떨어지고 콜백이 돌지 않는다.
2. `/auth/callback` 이 코드를 교환한 직후 `session.provider_token` 을 받는다. Supabase 는 provider token 을 보관·갱신하지
   않으므로 이 시점에만 얻을 수 있다.
3. 토큰의 `x-oauth-scopes` 에 `repo` 가 있고, 교환 결과가 연결을 시작한 회원과 같을 때만 봉인 쿠키에 담는다.
   (브라우저에 로그인된 다른 GitHub 계정으로 승인해 다른 회원으로 로그인된 경우에는 저장하지 않는다)
4. `?github=connected|denied|error` 로 원래 화면에 돌아와 결과 토스트를 띄우고, 연결되면 다이얼로그를 다시 연다.

GitHub 승인 화면에서 취소해도 기존 로그인 세션은 유지한다(일반 로그인 실패처럼 세션 쿠키를 지우지 않는다).

## 2. 권한과 조직 접근

- 요청 스코프는 `repo` 하나다. OAuth App 에는 비공개 저장소를 **읽기만** 하는 스코프가 없어 쓰기 권한까지 포함되지만,
  앱은 읽기 API만 호출한다.
- **토큰 권한은 저장소 단위**라 "본인 커밋만 읽는 토큰"은 만들 수 없다. 본인 커밋만 가져오는 것은
  `GET /repos/{owner}/{repo}/commits?author=<login>` 의 필터 결과이지 권한 경계가 아니다.
- 조직이 OAuth App 접근을 제한하고 있으면(새 조직의 기본값) 승인 화면의 **Organization access** 에서
  멤버는 **Request**, 소유자는 **Grant** 를 눌러야 한다. 요청은 조직 소유자가 승인해야 반영되고,
  그 전까지 해당 조직 저장소는 목록에 나타나지 않는다.
- 같은 스코프를 이미 승인한 적이 있으면 GitHub 가 승인 화면을 건너뛴다. 이때는 GitHub **Settings → Applications →
  Authorized OAuth Apps** 에서 앱을 열어 조직 접근을 요청한다.
- 로그인 앱의 승인 범위가 `repo` 로 넓어지므로, 이후 GitHub 로그인에서도 같은 승인이 유지된다(GitHub 승인은 누적된다).
- SAML SSO 를 쓰는 조직은 승인 과정에서 SSO 인증을 함께 요구한다.

## 3. 토큰 보관

- 토큰은 DB 에 저장하지 않는다. `iron-session` 으로 봉인한 httpOnly 쿠키(`github_token`, 30일)에만 둔다.
  브라우저 JS 는 토큰을 읽을 수 없고, 서버는 Server Action 실행 시점에만 꺼내 쓴다.
- 토큰과 함께 회원 id 를 봉인한다. 로그아웃 후 다른 계정으로 로그인하면 쿠키의 토큰을 쓰지 않는다.
- **연결 해제**는 이 브라우저의 쿠키만 지운다. 로그인용 앱의 승인이라 GitHub 쪽 승인을 철회하면 GitHub 로그인까지
  다시 승인해야 하므로 자동으로 철회하지 않는다. `repo` 권한까지 거두려면 GitHub 설정에서 직접 철회한다.

## 4. 커밋 수집 범위

1. `GET /user/repos?sort=pushed` 로 기준 시각 이후 push 된 저장소(최대 20개)를 고른다.
2. 저장소마다 `GET /repos/{r}/activity?actor=<login>&activity_type=push` 로 본인이 push 한 브랜치를 찾는다
   (막혀 있으면 기본 브랜치만 본다). 저장소당 최대 10개 브랜치.
3. 브랜치마다 `GET /repos/{r}/commits?author=<login>&since=<기준>` 으로 커밋을 모으고 SHA 로 중복을 없앤다. 머지 커밋은 제외.

기준 시각은 **오늘 이전 날짜의 마지막 보고서 작성 시각과 오늘 0시 중 이른 쪽**이고, 최대 14일 전까지만 거슬러 올라간다.
커밋 작성 이메일이 GitHub 계정에 연결돼 있지 않으면 `author` 필터에 잡히지 않는다.

## 5. 온디바이스 분류

- Chrome 데스크톱(Prompt API 지원, 약 148+)에서만 AI 분류가 동작한다. 그 밖의 브라우저는 저장소 기준 규칙 분류로 대체한다.
- Gemini Nano 는 한국어를 공식 지원 언어로 받지 않아(`ko` 선언 시 unavailable) 영어로 선언하고 한국어 텍스트를 넣는다.
- 분류 단계와 PoC 근거는 `lib/commit-classifier/prompts.ts` 주석 참고.

## 6. 보정 메모리

회원별로 이 기기의 localStorage(`commit-import-memory:<회원 id>`)에 사용자가 고친 표기를 기억해 다음 분류에 쓴다.

| 기억하는 것             | 예                                                           | 다음 가져오기에서                                                                 |
| ----------------------- | ------------------------------------------------------------ | --------------------------------------------------------------------------------- |
| 저장소 → 프로젝트명     | `todo-report-generator` → "일일 업무 보고 서비스"            | AI 판정 없이 그 프로젝트(폼에 있으면 기존, 없으면 그 이름의 새 프로젝트)에 붙인다 |
| `저장소#scope` → 작업명 | `todo-report-generator#export` → "보고서 내보내기 기능 개발" | 폼에 같은 이름의 작업이 있으면 그 작업에, 없으면 그 이름의 새 작업으로 묶는다     |
| 세부 항목 표기          | "주석 추가" → "코드 주석 보강"                               | 같은 제목은 그대로 바꾸고, 나머지는 최근 보정 예시로 사용자 표기에 맞춰 다시 쓴다 |

- 미리보기에서 확정할 때 한 번, 가져온 항목을 폼에서 더 고친 뒤 **보고서를 저장(복사)할 때** 다시 읽어 반영한다.
- 세부 항목은 AI 가 필요하다고 판단한 작업에만 제안한다. 사용자가 제안 문구를 실제로 고친 경우만 표기로 배운다(AI 문구를 다시 배우지 않는다).
- 기기별 저장이라 다른 기기에서는 처음부터 다시 쌓인다.

### 분류에서 뺄 저장소

개인 프로젝트처럼 보고서에 넣지 않을 저장소는 미리보기의 저장소 칩에서 **제외**를 누른다. 제외한 저장소는 다음 가져오기부터
커밋 조회 자체를 건너뛰고, 다이얼로그 하단 **제외한 저장소 N개** 메뉴에서 언제든 해제할 수 있다(해제하면 다시 불러와 분류한다).
